System Architecture — what we built

Overview

SoMaCo Trade Control is a prediction-market trading engine built on Kalshi (live, CFTC-regulated) and Polymarket (on-chain, dormant until funded). The system runs 34+ autonomous Python daemons on a Windows host, supervised by a process manager, with a Vercel-hosted Next.js dashboard that reads from a Supabase Postgres ledger (the shared source of truth).

Substrate

  • GYST UUIDv8 — every order, fill, position, and settlement gets a 128-bit self-describing UUID with embedded type codes and bitmask routing. Not auto-increment IDs.
  • Supabase Postgres — the cloud ledger (uuid_orders, uuid_fills, uuid_positions, equity_history, mc_state). Vercel reads this; local daemons write to it.
  • mc_state — a key-value state table where every daemon publishes its heartbeat and state (daemon:*, account:equity, evidence:lanes, sweep:pending, etc.)

Daemon Fleet (34+ processes)

  • Core: supervisor, mission_control, vault, ws (WebSocket), tick_service, governor, oracle, bridge, evidence, ingest
  • Trading: scalp (mean-reversion), trend_engine x4 (BTC/ETH/SOL/XRP), maker, xvenue (cross-venue arb), promoter, btctrend, poly_exec, moonshot, parlay, speed-btc/eth
  • Signal: x_watcher (X/Twitter), shadow_index (whale tracking), news_supply_engine, copier, uptick_spiral (forecast scoring)
  • Paper: dry_run x4 ($1/$3 clip comparison at 10s/20s/25s/$1.50x8 cycles)
  • Ops: sweep_watch, calendar_engine, funding_feed, recovery_engine, agent_status

Trading Lanes

  • momentum-15M — 15-minute crypto directional bets (BTC/ETH/SOL/XRP/DOGE)
  • parlay-tails — multi-game MLB composite bets (KXMV series)
  • sports — individual game markets (KXMLBGAME)
  • supply-chain — WTI/CPI economic event markets
  • news — NASDAQ/SP500/WHEAT event markets

Edge Finder

The /api/trade/edge endpoint fetches live Kalshi KXMLBGAME markets and compares each market's YES/NO ask price to a model win probability. The edge = model_prob - market_price. If the edge is positive, the model thinks the market is mispriced — betting there has positive expected value.

Failure Harness

After two bluescreen crashes (bugcheck 0x124 WHEA — hardware PCIe fault), we built a failure harness at /d/somacosf/scripts/failure_harness/ that captures crash data, takes system snapshots, generates recovery reports, and auto-restarts the daemon fleet. 51/51 verification checks pass.

Deployment

  • Vercel — Next.js 14 app at mc.somacosf.com (trade terminal) + time.somacosf.com (AI Times) + tim.somacosf.com (guest)
  • Supabase — cloud Postgres ledger (TRADE_DATABASE_URL env var)
  • Local — Windows OMEN-01, Python daemons via uv venv, supervisor.py launches all daemons headless via pythonw.exe
