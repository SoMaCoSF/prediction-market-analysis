## 1. The v3.0.0 Bit Layout and Its Evolution

**Canonical layout (signal-lattice lineage, "v2.0.0/v3.0.0"):** 128 bits, RFC 9562 UUIDv8, identity in the high word, signal state in the low word (`582fdee4` math proof; `b32caf04` thesis; `5c678c93` state audit; `38aa8c04` protocol master; `fd0a7892` Says master):

```
HIGH: type(12) | namespace_fnv1a12(12) | timestamp_sec(24) | ver=8(4) | fractal(12 = depth4|domain4|gen4)
LOW:  variant=0b10(2) | provenance(4) | signal_u16(16) | content_hash/random(42)
```
Bit accounting 12+12+24+4+12+2+4+16+42 = 128, verified field-by-field with shift tables and a zero-dependency Node test harness (`uuid-math.test.mjs` + `harness-meta.test.mjs`, which injects known corruptions to prove the harness isn't a rubber stamp) (`b32caf04`).

**Evolution across the corpus (oldest → newest):**

1. **Proto (IP Catalog era, `ca605d5f` / `739e46b0`):** UUIDv7-like — 48-bit ms timestamp, ver(4), rand_a(12), var(2), **3-bit type**, rand_b(61). Plus SSFDE content-hash UUIDs and the Dual UUID (private/HMAC-derived public) system.
2. **PopSoc/Fractal Protocol v2.0 (`28a8a018`, 2026-02):** 12-bit type (4096 codes), 12-bit ns, 24-bit **seconds** timestamp, ver, fractal(12), then **variant(2) + crypto-random(62)** — no provenance/signal fields. The Poincaré browser briefs (`e758ea44`, `b612b9b5`) use this same layout.
3. **Signal-lattice v2.0.0 (2026-04/05, `582fdee4`, `5c678c93`):** the 62 random bits are carved into provenance(4) + signal(16) + deterministic content-hash(42). Typed payload "casts" reinterpret the 62-bit low payload per type code (AERO_FORECAST, HEARTBEAT parentRef(48)+seq(14), etc.), each proven to sum to exactly 62 bits.
4. **Current `gyst.py` (v3.0.0):** high word matches the canonical spec exactly; the low word **deviates from the gist spec**: it packs `variant(2) | signal_q16(16)<<44 | provenance(4)<<40 | 40-bit SHA-256 entropy of identity_str` — i.e., signal and provenance are swapped relative to `582fdee4`'s `prov<<58 | sig<<42 | hash42`, entropy is 40 bits (not 42) and seeded from `identity_str` alone rather than the full field tuple, and the docstring's own comment ("provenance… 2 bit low, payload 60 bit") disagrees with the code (payload masked to 62 bits, parse reads signal at `>>44`). Cross-implementation decode of gist-era UUIDs with `gyst.py` would misread provenance/signal.
5. **Divergent variants:** the Jensen Huang brief (`f006cdd9`) describes an 8-bit generation + "62 bits entropy + millis" variant, and expands GYST as "General-purpose Yield-bearing Semantic Token" — a pitch-side fork not matching any implementation.

**Known limitation, consistently documented:** 24-bit seconds timestamp wraps every 2²⁴ s ≈ 194.18 days; framed as acceptable because "GYST tokens are signals, not permanent identifiers" (`b32caf04`). A critical **ms-vs-seconds bug** (cycle of 4.66 hours instead of 194 days) was found and fixed 2026-02-15 (`28a8a018`, Appendix A).

## 2. Mathematical Claims and Proofs

- **Bit-exactness proofs** (`582fdee4`, `b32caf04`): shift tables proving no overlap/gap in either 64-bit word; hex format 8+4+4+4+12 = 32 chars; FNV-1a-32 with published constants (0x811C9DC5 / 0x01000193, `Math.imul` for JS overflow) XOR-folded to 12 bits; signal quantization `u16 = clamp(floor(s×65535))`, invertible with 1/65535 ≈ 0.0015% resolution; Pyth deviation mapping `signal = clamp(0.5 + 5·dev)` with algebraic derivation k = 0.5/R for R = 10%, and spike detection as a standard z-score (σ = |spot−EMA|/conf, 2σ threshold). Verdict in both gists: "No mathematical errors found."
- **Collision bounds** (`28a8a018`, Proofs 2–3): total address capacity 2¹¹⁰ ≈ 1.3×10³³; within same type+namespace+second the 62-bit random field gives birthday bound n ≈ 1.2·√2⁶² ≈ 2.58×10⁹ same-second mints for 50% collision; at observed scale (~920 entities) P ≈ 10⁻¹⁴. (For the 42-bit content-hash lineage the effective guard is smaller — 2⁴², birthday ≈ 2.5M per identical structural tuple — but collisions there are *intended* to mean "same content.")
- **O(1) bitmask decode ("wirespeed")** (`f006cdd9`, `fd0a7892`, `cbed3385`): the routing claim is that type/provenance/signal inspection is "4 byte-shifts, 0 tokens" versus a DB lookup + JSON parse, converting provenance filtering from ~O(n) scan to O(1) mask per identifier. This is true per-message; the `cbed3385` claim of "Spatial Queries (O(1))" for *convex hulls and radius queries* over the point cloud is an **uncorrected overclaim** — those are not O(1) operations.
- **TurboQuant maths** (`cea69325`, `38aa8c04`, `783de3d3`): TurboQuant (arXiv:2504.19874) = 3-bit Lloyd-Max key quantization after random rotation + 2-bit symmetric value quantization; reported 5–8× KV memory reduction, 2× token capacity (457k→914k on RTX 5090, 30 GB freed), decode/prefill roughly parity or better. The GYST binding: each layer's normalized MSE quality becomes the 16-bit signal of a `0x200 TURBO_KV_STATE` UUID — "UUID = addressable KV slot"; a 64-layer model's memory health is 64 UUIDs. `cea69325` argues GYST's 16-bit signal field is the same Lloyd-Max principle at 65,536 centroids. The benchmarks are the *paper's*, not independently GYST-validated; `38aa8c04` correctly labels them "reported measured results (external)."
- **rand42 audit** (`20084641`, P0): commit `0bd8b92` (2026-04-20) replaced the deterministic low-42 with `crypto.randomBytes` — a hallucination of the spec word "random" (which meant "not structurally assigned," not "cryptographically random"). Consequences: dedup via `INSERT OR IGNORE` never fired, DB bloat, provenance chain broken; a `[:16]` log truncation masked it by making distinct UUIDs look identical. Fixed in `b58447a` (2026-04-28) with `deterministicLow42 = first 42 bits of SHA-256(type:ns:ts:depth:domain:gen:sig16:prov:contentKey)`; the audit also caught a pre-existing Python bug (30-bit entropy masked into an 18-bit field, silently discarding 12 bits). Permanent rule: *"GYST UUID v8 bits are never random."*
- **Content-address completeness** (`5c678c93`): follow-up audit showing the bit layout was correct post-fix but the contentKey was **under-seeded** — `score` (divergence z-score) and `confidence` were in JSON meta but not hashed, so a 2.34σ and a 4.71σ observation of the same market/second/price collided to one UUID. Fix: append `round(score×1000)`/`round(conf×1000)` to the contentKey. Defines "same signal" precisely as the full tuple. Residual risk: wall-clock default timestamp breaks idempotency on retry.

## 3. Fractal / Spawn Hierarchy Model

The 12-bit fractal coordinate = depth(4) | domain(4) | generation(4), pack/unpack proven overlap-free (`28a8a018` Proof 5; `582fdee4`). **Depth** is recursion level in the entity graph (city→district→venue→item = 0–3; PopSoc max observed depth 4: layer←canvas←event←user). **Domain** is a 4-bit vertical code — but the domain table is *lineage-specific*: PopSoc uses core/content/political/dining/wine… (`28a8a018`), the signal lattice uses CORE/MARKET/…/ENERGY/EMERGENCY (`582fdee4`), and `cbed3385` a third set — a genuine cross-gist inconsistency. **Generation** is a fork/mutation counter. Spawn trees (`28a8a018` §11): user(d0)→event(d1)→canvas(d2)→view/layer(d3); enterprise→segment→brand→brand_product; two investigative verticals (Mirage/Ossuary) "convergently evolved" identical 6-type structures. Parent-child spawning is realized concretely in the NYC spatial city (`cbed3385`): a building's BBL deterministically seeds a depth-0 parent UUID which spawns agent/contract/wallet children at depth 1, escrow/amendment at depth 2; HEARTBEAT payloads carry a 48-bit parentRef enabling recursive-CTE lineage replay. Domain-slot sufficiency proof: 16 slots with 0xF as auto-assign overflow; type code remains ground truth if domains exhaust. **0x600 plane** (`29e78562`): a reserved type block `0x600–0x60F TYPE_INFORMATION` giving signage/information a *temporal* plane — SIGN_SURFACE/ZONE/PLACEMENT plus INFO_MESSAGE/SCHEDULE/WINDOW/TIMELINE/REVISION/RENDER/DISTRIBUTION/INTERACTION — a minimum envelope so every deployed infographic is traceable across what/when/where/how-delivered/how-used. Implemented in PopSoc's deploy engine. (Note: in the signal-lattice registry 0x600 is also glossed as "InfoTower archetype," `cbed3385`.)

## 4. GeoHex / Spatial Claims

The spatial story is a **projection layer over the UUID, not GPS in the bits**. Key claims:

- **Hex lattice addressing** (`cbed3385`, `75c8aa41`): namespace bits deterministically map an entity to a hex-grid position; the aerodrome board renders "hex board, UUID cells, icosphere shell." HEXAPHEXAH/hex-map-wfc forks supply hex tiling machinery (`54873ca9`).
- **Icospheric point cloud** (`cbed3385`, `43a1f290`, `77f6b87d`): position (x,y,z) is *derived* from type+namespace+random bits; fractal **depth selects the shell** (depth 0 outermost → depth 8–15 innermost); RGB color carries a 24-bit LENS-encoded steganographic payload; Dither3D ("Surface-Stable Fractal Dithering," runevision fork → DitherCrypt core) supplies tamper-evident surface encoding. The PRD claims "deterministic 3D spatial encoding of UUID properties, 182–248 bits/point with RGB LENS-keyed dithering" (`77f6b87d`). `43a1f290` argues icospheric geometric traversal beats Memori's SQL for memory retrieval — explicitly speculative ("potential"), no benchmark.
- **Poincaré Icosapheric Browser** (`e758ea44`, `b612b9b5`): evolve the `poincake` hyperbolic note-taking fork so every note/arrow is a GYST UUIDv8 (fractal-lineage layout: ts-seconds, fractal12, variant+62-bit random), with `visualSeedForUUID` deriving dither3d-style glyphs, placement heuristics in Poincaré-disk space (z = r·e^{iθ}) constrained to preserve Möbius invariants.
- **GPS/geoloc:** *no gist encodes lat/lon into UUID bits.* Real GPS coordinates live beside UUIDs in entity rows (restaurants, `271c2574`; flightr airports). The UUID "encodes" location only indirectly: namespace = city/source hash, hex/shell position = deterministic function of the bits, and the BBL→UUID mapping ties an ID to a physical tax lot. Any claim that a GYST UUID *is* a geolocation should be treated as unsupported by the corpus.
- **ManimGL visualization** (`38aa8c04` `gyst_lattice_cortex.py`): icosphere + 11 Says-Network city nodes — confirming the icosphere is a rendering metaphor ("the full GYST address space from outside," `36d0eb8a`), which even the flightr assessment calls "abstract" versus real geography (`edecd65d`).
